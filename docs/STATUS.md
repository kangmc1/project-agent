## 2. 결정한 것
1. 주제: **handoff 안정성** — 정보가 역할 경계와 압축을 거치며 얼마나 깨지는가를 시스템 속성으로 수치화. 탐지기 정확도가 아니라 정답 by construction.
2. 데이터: 합성 시나리오(폐쇄형, world 없음, 같은 모델). 실제 데이터(TraceElephant)는 "실제로 일어난다"는 근거 층.
3. 판정: 규칙 매처. LLM judge는 부품·비교군.
4. 행동: 에이전트 선택으로 정의(4지선다). 분포는 logprobs로 직접 읽음(샘플링 아님).
5. D3: 정책 벡터 위의 **선형 프로브**로 손실 예측(그리드 데이터로 학습, 시나리오 단위 교차검증). 은닉 상태 프로브는 시간 남으면.
6. 폭(병렬)은 1로 본 실험, 3은 확장 축으로 문서화.
7. 사람 라벨(gold 20)은 선택 사항으로 강등. 실제 데이터 근거는 자동 추출 수치(59/75, 3%)로 충분.

## 3. 우리 시스템에서 handoff의 구체 정의 (지금까지 러프했던 부분)
워크플로우 한 라운드에서 정보가 경계를 넘는 사건은 네 가지이고, 각각에 "무엇이 넘어가는가 / 무엇을 재는가"를 고정한다.

| 경계 | 송신 → 수신 | 넘어가는 것 (artifact) | 수신자가 보는 것 | 지금 재는 것 | 변수 |
|---|---|---|---|---|---|
| **B1 지시** | Orchestrator → Agent | (action_type, target, instruction) | shared: 초기 대화록 + 보고 전부 / summary: 현재 state만 | (직접 측정 없음; B2·B3에서 결과로 관측) | 가시성 |
| **B2 반환** | Agent → Orchestrator | report | Orchestrator의 다음 라운드 입력(최근 보고 4개 + 이력) | 보고 속 날조 값(초기 문맥에 없는 숫자형 토큰), Verifier의 APPROVE/REVISE | 폭(1/3): 병렬 보고 간 상충 |
| **B3 압축** | Orchestrator(t) → 팀(t+1) | 새 state (free \| json) | 이후 모든 에이전트의 유일한 문맥 | 심어 둔 의무의 보존/변조/소실/승격, 단어 수, **압축 전후 정책 JSD**, 가드 복구 수 | 예산, 포맷, 가드 |
| **B4 최종** | Orchestrator → 사용자 | final deliverable | 사용자 | 제약 보존, 금지 위반(부정어 인식), 승격, 날조 값 | — |

- 심어 둔 의무 8개는 초기 대화록에만 있고 어느 에이전트에게도 목록으로 주어지지 않는다 → "중요한 것을 알아서 지켜 내는가".
- 라운드별 **정책 불확실성** = 상태만 보고 잰 4지선다 분포(엔트로피, 상위 차). 실제 결정은 평가문 뒤에 따로 내림.
- **프로브 라벨**: 각 압축 B3에서 손실 여부(보존율 < 1 또는 승격 > 0). 입력: 직전 라운드의 정책 벡터·엔트로피·라운드·단어 수·JSD.
- 안정성 지표: 압축 횟수별 보존율 곡선 S(k), 최종 답 보존율, 승격율, 날조율, 금지 위반율, Verifier REVISE율, 토큰. 조건(가시성×포맷×가드)별 비교.
